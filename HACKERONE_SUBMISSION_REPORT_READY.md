## 2. Executive Summary

During an authorized security assessment of ABB assets, a Cross-Origin Resource Sharing (CORS) misconfiguration was identified on the production host `qms.lmg.motion.abb.com.cn`. 

The web server responds with `Access-Control-Allow-Origin: *` to cross-origin HTTP requests originating from arbitrary, untrusted third-party domains (e.g., `https://evil.com`). This policy effectively disables the Same-Origin Policy (SOP) protections enforced by modern web browsers, permitting unauthorized third-party domains to initiate cross-origin requests and read server responses.

---

## 3. Technical Details & Vulnerability Analysis

The Same-Origin Policy (SOP) is a critical security mechanism that restricts how a document or script loaded by one origin can interact with a resource from another origin. 

When a server sets:
```http
Access-Control-Allow-Origin: *
```
it explicitly instructs any visiting client browser that **any domain on the Internet** has permission to read the responses generated by this endpoint.

### Key Observation:
- Target Endpoint: `https://qms.lmg.motion.abb.com.cn/`
- Discovered Endpoints: 45 internal routing paths mined from client scripts.
- HTTP Request with Header `Origin: https://evil.com` receives:
  `Access-Control-Allow-Origin: *`

## 4. Step-by-Step Proof of Concept (PoC)

### Step 1: Execute HTTP Request via cURL
Run the following cURL command from any terminal to verify the reflected wildcard CORS policy:

```bash
curl -i -s -k -X GET \
  -H "Origin: https://evil.com" \
  "https://qms.lmg.motion.abb.com.cn/"
```

### Step 2: Observed HTTP Response Headers
The server responds with the permissive CORS header in the response:

HTTP/1.1 200 OK
Server: nginx
Date: Sat, 08 Aug 2026 01:33:58 GMT
Content-Type: text/html; charset=utf-8
Connection: keep-alive
Access-Control-Allow-Origin: *

Access-Control-Allow-Headers: Content-Type, Authorization, X-Requested-With

## 5. Security Impact

1. **Bypass of Same-Origin Policy (SOP):** Any malicious website visited by an authenticated or internal user can read application data from this host without restriction.
2. **Data Exposure:** Sensitive operational metrics, internal platform routes, and status responses from the ABB Motion quality management system are exposed to arbitrary origins.
3. **Cross-Origin Reconnaissance:** Attackers can dynamically map and extract endpoints across the internal motion quality management platform.

---

## 6. Remediation & Recommended Fix

1. **Restrict `Access-Control-Allow-Origin`:**
   Replace the wildcard `*` with a strict, server-side whitelist of trusted ABB domain origins (e.g., `https://*.abb.com` or `https://*.motion.abb.com.cn`).
   
2. **Avoid Default Wildcards in Production:**
   Ensure web server configurations (Nginx / API Gateway) do not return `*` unless the resource is genuinely public and intended for global unauthenticated read access.

3. **Sample Nginx Configuration Fix:**
   ```nginx
   # Restrict CORS to trusted ABB origins only
   if ($http_origin ~* "^https?://(.*\.)?(abb\.com|abb\.com\.cn)$") {
       add_header "Access-Control-Allow-Origin" "$http_origin" always;
       add_header "Access-Control-Allow-Methods" "GET, POST, OPTIONS" always;
       add_header "Access-Control-Allow-Headers" "Authorization, Content-Type" always;
   }
   ```
